# Подключить evo к AI-агенту одной вставкой

Вставьте своему агенту (Claude Code, Claude Desktop, Cursor, VS Code,
Gemini CLI, Codex) одну строку:

```text
Настрой evo по https://github.com/cloud-ru/evo-cmcp/blob/main/docs/agent-setup.md
```

Агент проверит evo, при необходимости установит его и начнёт подключение.
При локальном входе evo откроет браузер. Выберите проект и нажмите
**«Выдать доступ»**. Затем агент покажет изменение настроек вашего
MCP-клиента и попросит согласие на запись. Как устроен доступ и как его
отозвать — в [auth.md](auth.md#вход-через-браузер-evo-login).

Вход через браузер работает, когда агент и браузер — на одной машине. По SSH
и в контейнере его нет: тогда ключ создаёте вы в личном кабинете Cloud.ru и
выполняете `evo configure` сами ([auth.md](auth.md#2-ключ-доступа)).

---

## Инструкция для агента

Ты подключаешь evo (консольную утилиту и MCP-сервер для Cloud.ru Evolution) для человека,
с которым работаешь. Выполняй шаги по порядку. Кратко сообщай человеку о
значимых действиях на его языке. Если у тебя нет локальной оболочки или
доступа к машине, где установлен его MCP-клиент, дай человеку команду
только для текущего шага на его машине. Дождись результата и продолжай.

### Правила

- **Доступ выдаёт только человек.** Ключ доступа появляется, когда человек
  нажимает «Выдать доступ» на странице Evolution CMCP в своём браузере. Сам
  никогда не открывай, не запрашивай и не отправляй эту страницу и любой
  адрес `127.0.0.1` — ни браузерным инструментом, ни curl, ни другим
  HTTP-запросом. У `evo login` нет флага, который выдаёт доступ, — не ищи
  его. Ссылку, которую печатает `evo login`, не пересказывай, не отправляй и
  не открывай: ни в чат, ни в другой канал, ни браузерным инструментом. Не
  проси человека прислать её тебе — человек открывает её сам из терминала на
  этой же машине. Запуск команды входа из шага 2 поручен тебе. Системный
  браузер открывает сам evo.
- **Не касайся секрета.** Не проси у человека ключ или секрет в чате, не
  печатай и не читай файлы настроек и ключей evo, не передавай секрет в
  командной строке.
- **Установку evo делай сам, запись в настройки клиента — после согласия.**
  Строка «Настрой evo по…» — согласие человека на установку evo (шаг 1):
  скажи, что ставишь, и ставь. Изменение настроек клиента (шаг 3) покажи
  diff'ом и выполняй после согласия человека.
- **При сбое обязательного шага** приостанови настройку, сообщи причину и следующий доступный шаг.
  Из вывода исключи секреты и ссылку входа. Для установки используй критерии
  шага 1, для отказа в записи настроек клиента — порядок из шага 3.

### 1. Установи или обнови evo

Выполни `evo version`.

- Печатает версию 1.9.1 или новее — переходи к шагу 2.
- `evo` не найден или версия старше — установи его сам, сказав человеку,
  что ставишь. Установщик скачивает последний стабильный выпуск, сверяет
  sha256 архива (и подпись, если есть `cosign`) и кладёт бинарь в
  `~/.local/bin`; прав администратора не нужно.
  - Linux и macOS — выполни в оболочке:
    `curl -fsSL https://raw.githubusercontent.com/cloud-ru/evo-cmcp/main/install.sh | EVO_ZSHRC=0 sh`
  - Windows (PowerShell; для ARM — `$arch = "arm64"`):

    ```powershell
    $v = (Invoke-RestMethod https://api.github.com/repos/cloud-ru/evo-cmcp/releases/latest).tag_name.TrimStart("v"); $arch = "amd64"; $dir = "$env:LOCALAPPDATA\Programs\evo"; $base = "https://github.com/cloud-ru/evo-cmcp/releases/download/v$v"; $zip = "evo_${v}_windows_$arch.zip"; $tmp = New-Item -ItemType Directory -Force "$env:TEMP\evo-$v"
    Invoke-WebRequest "$base/$zip" -OutFile "$tmp\$zip"; Invoke-WebRequest "$base/checksums.txt" -OutFile "$tmp\checksums.txt"
    $want = ((Select-String -Path "$tmp\checksums.txt" -Pattern ([regex]::Escape($zip) + '$')).Line -split '\s+')[0]; if ($want -ne (Get-FileHash "$tmp\$zip" -Algorithm SHA256).Hash.ToLower()) { throw "sha256 mismatch" }
    Expand-Archive "$tmp\$zip" -DestinationPath $dir -Force
    if (($env:Path -split ';') -notcontains $dir) { [Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path", "User") + ";$dir", "User"); $env:Path += ";$dir" }
    ```

    Скрипт кладёт `evo.exe` в `%LOCALAPPDATA%\Programs\evo` и, если этого
    каталога нет в `Path` пользователя, добавляет его туда навсегда — скажи
    об этом человеку до запуска.

  Затем снова выполни `evo version`. Если `evo` не находится, а установщик
  сказал, что каталога нет в `PATH`, — запускай `~/.local/bin/evo` (Windows —
  `$env:LOCALAPPDATA\Programs\evo\evo.exe`) полным путём до конца
  настройки и скажи человеку, какую строку добавить в профиль оболочки.
- Если `evo version` после установки по-прежнему печатает старую версию,
  evo стоит ещё где-то (Homebrew, другой каталог в `PATH`): не ставь
  повторно — назови человеку путь (`command -v evo`, на Windows
  `(Get-Command evo).Source`) и спроси, какую копию оставить.
- На Linux и macOS установщик после записи бинаря также настраивает
  автодополнение оболочки. Если установщик завершился с кодом 0, проверки
  выпуска прошли, а единственные предупреждения возникли на этом
  необязательном этапе, запусти установленный бинарь по пути из вывода,
  например `"$HOME/.local/bin/evo" version`. При успешном выводе ожидаемой
  версии выпуска (1.9.1 или новее) **сразу переходи к шагу 2**. Предупреждения
  об автодополнении в ответ пользователю выносить не нужно. Сообщение
  `Broken pipe` само по себе не определяет, какой этап завершился ошибкой.

- Установка упала (нет сети, хэш не сошёлся) — не обходи проверку и не
  качай бинарь другим способом: покажи человеку ошибку и ссылку
  https://github.com/cloud-ru/evo-cmcp/blob/main/docs/install.md.

### 2. Вход: доступ выдаёт человек

Проверь, где ты работаешь. Если ты работаешь по SSH, в контейнере или на
другой машине, чем браузер человека, вход через браузер не сработает: попроси
человека создать ключ доступа в личном кабинете Cloud.ru и самому выполнить
`evo configure --profile agent`
(https://github.com/cloud-ru/evo-cmcp/blob/main/docs/auth.md), дождись, когда
он скажет, что готово, и переходи к шагу 3.

При локальной работе **сам начни вход**, если можешь выполнить команду
в терминале на машине пользователя, который ему виден. Скажи:
«Сейчас evo откроет браузер. Выберите проект и нажмите “Выдать доступ”».
Затем запусти:

```sh
evo login --for agent
```

Если в шаге 1 понадобился полный путь к evo, используй его здесь и далее.
Браузер по умолчанию открывает сама команда. Оставь команду запущенной
и дождись результата (до 5 минут). Доступ в браузере выдаёт человек.

- Если браузер не открылся, а человеку виден терминал, попроси его открыть
  напечатанную там ссылку в браузере на той же машине. Ссылку в чат не копируй.
- Если у тебя нет возможности выполнить команду в видимом человеку терминале
  или среда запретила её запуск, объясни причину. Если вход уже ожидает
  ответа в невидимом терминале, прерви его. Дай человеку команду входа
  с проверенным путём к evo для запуска в его терминале на этой машине.
  После сообщения об успешном завершении переходи к шагу 3.
- Если команда задаёт вопрос в терминале, передай вопрос человеку.

- Код выхода 0: ключ записан в профиль `agent`. Переходи к шагу 3.
- Любой другой код: остановись и покажи человеку ошибку и подсказку, которые
  напечатал evo, — без ссылки входа. Если страницу закрыли без «Выдать
  доступ», человек доступ не выдал — спроси, попробовать ли ещё раз.

### 3. Подключи evo к себе

Выбери свой клиент:

| Ты работаешь в | `--client` |
|---|---|
| Claude Code | `claude-code` |
| Claude Desktop | `claude-desktop` |
| Cursor | `cursor` |
| VS Code (Copilot) | `vscode` |
| Gemini CLI | `gemini` |
| Codex | `codex` |

Сначала покажи изменение:

```sh
evo agent setup --client <клиент> --profile agent --dry-run
```

Покажи человеку diff и дождись согласия. После согласия сам выполни ту же
команду с `--yes` вместо `--dry-run`, сохрани выбранный клиент и профиль.

Если запись завершилась отказом в доступе к файлу настроек **или к временному
файлу рядом с ним**, сообщи, какой шаг не удался. Дай человеку ту же
согласованную команду с фактическим путём к evo и именем его клиента для
запуска в обычном терминале на этой машине. Подставь значения сам, чтобы
команду можно было скопировать целиком. Повторный вход, `sudo` и изменение
прав на каталог для этого шага не нужны. После успешной записи переходи
к шагу 4.

Если клиента нет в таблице, выведи параметры сервера командой
`evo agent setup --client cursor --profile agent --print json`. Используй
их как образец для настройки MCP в фактическом клиенте. Если у тебя нет
доступа к его настройкам, передай параметры человеку и укажи, где их
добавить.

Без `--profile` клиент подключается к профилю по умолчанию, то есть к ключу
человека. Если в профиле `agent` есть ключ из `evo login --for agent`,
`evo agent setup` без `--profile` предупреждает об этом до diff и называет
команду с `--profile agent`.

### 4. Передай работу

Попроси человека перечитать MCP-серверы в клиенте или перезапустить клиент
(Claude Desktop — закрыть полностью и открыть снова), потом вернуться и работать.
После перезапуска проверь, что инструменты `evo` на месте: вызови
инструмент `whoami` — он назовёт проект и роли ключа (из терминала ключ и связь с API
можно проверить командой `evo doctor --profile agent`). Скажи человеку, что evo подключён, к
какому проекту, и спроси, с чего начать: например, показать ВМ проекта
(`vm_list`) или развернуть его `docker-compose`-проект (`deploy_plan`).

У ключа — роль «Администратор проекта» на выбранном проекте на срок, который
выбрал человек. Изменение в облаке приходит с превью evo, а одобрение вызова
инструмента в клиенте — защита человека: давать его за человека не тебе.
Закрыть доступ раньше срока — по тому, откуда ключ:

- Ключ из `evo login --for agent`: `evo logout --profile agent`. Команда
  удаляет этот ключ в облаке и профиль. Роль сервисного аккаунта человек
  снимает сам в личном кабинете Cloud.ru → «Сервисные аккаунты»; токены,
  выданные ключу раньше, действуют до времени, которое назовёт `evo logout`
  (не дольше часа).
- Ключ из `evo configure` или личного кабинета: `evo logout` его не удаляет,
  а удаляет только профиль. Ключ человек удаляет сам в личном кабинете
  Cloud.ru → «Сервисные аккаунты»; затем `evo logout --profile agent` убирает
  профиль с этой машины.

Подробно — [auth.md](auth.md#вход-через-браузер-evo-login).
